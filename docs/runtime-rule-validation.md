# 実行時計算のルール検証

## 目的

この文書は、事前計算済み確率分布を受け取った後にJavaScriptで行う達成値、成功率、ダメージ、バックトラックの計算が、[`dice-rules.md`](./dice-rules.md)の仕様と一致することを検証する方針を定義します。計算手順は[`runtime-calculation-algorithms.md`](./runtime-calculation-algorithms.md)、対応するテストは`tests/runtimeRuleValidation.test.js`です。

事前計算器そのものの確率計算は[`precomputation-validation.md`](./precomputation-validation.md)で検証します。旧実装との移行比較は意図しない挙動変化の発見には有用ですが、旧実装と現行実装が同じ誤りを持つ可能性を排除できません。そのため、この文書で扱うテストは`tests/legacy/LegacyCalculator.js`を参照せず、ルールから直接導いた期待値と比較します。

## 検証対象

| 対象 | 実行時に行う処理 | 主な検証項目 |
| --- | --- | --- |
| 判定 | 技能値の加算、《妖精の手》等の適用、成功率と対決結果の計算 | 自動失敗、ファンブル、難易度0、達成値0、複数回の`yousei`、対決の同値 |
| ダメージ | 命中結果からのダメージダイス数決定、固定値とダイス軽減の適用 | 10単位の境界、対決失敗、固定値を加える順序 |
| バックトラック | 振るダイス数の決定、Dロイスの効果、最終侵蝕率の区分 | 1倍振り、2倍振り、追加振り、全選択肢、通常と「不死者・悪夢」の閾値 |

疎形式の展開、上限集約、FFT、静的アセットの構造検証は、それぞれの単体テストで扱います。Vueフォームの入力制約、表示、ブラウザ操作はこのテストの対象外です。

## 独立した期待値の作り方

### 判定

`calculateScore`にはテスト用の疎な確率分布を注入します。事前計算済み`dx`やPython生成器を期待値の作成に使わず、自動失敗、ファンブル、通常の出目を任意の比率で配置して、技能値と成功判定だけを分離して検証します。

最終分布のインデックス0には、自動失敗・ファンブルと、技能値補正によって0になった通常結果の両方が入ります。難易度0では前者だけを失敗とする必要があるため、`calculateScore`が返す`failureProbability`を別に検証します。

`yousei`は、現在のダイス部分の達成値を10単位で切り上げた後、1ダイスの判定結果を加える手順を、決定的な点分布で検証します。ダイス数0では指定回数にかかわらず自動失敗を維持することも境界値として固定します。

対決ではテスト内で少数の達成値と確率を直接配置し、アクション側の達成値がリアクション側より大きい組み合わせだけを合計します。これにより、同値をリアクション側の勝利とする規則を実装とは独立して検証します。

### ダメージ

通常D10合計の期待分布は、テスト内の単純な三重ループによる畳み込みで作成します。本番のFFT、`dr`生成ロジック、旧Calculatorは使用しません。

達成値9と10を固定して、それぞれ1D10と2D10になることを比較します。対決が同値なら攻撃力にかかわらずダメージ0になることも検証します。

固定値とダイス軽減の順序は、1D10へ固定値5を加えてから1D10を引くケースを使用します。最終ダメージ0の理論確率は`15 / 100`であり、途中で先に0へ丸める実装とは結果が異なるため、順序の回帰を検出できます。

### バックトラック

通常D10合計はテスト内の単純な畳み込み、《屍人》は少数ダイスの全出目列挙から期待分布を作成します。最終侵蝕率を出目ごとに直接計算し、通常の5区分、「不死者・悪夢」の6区分、成功・失敗の2区分へ振り分けます。

「なし」「戦闘用人格・生きる伝説」「生還者」「不死者・悪夢」「屍人」「戦友(通常)」「戦友(強化)」を同じパラメータ化テストで検証します。期待値側は各選択肢のダイス数補正、使用する分布、成功上限を明示した表から計算し、本番の`DLOIS_RULES`を参照しません。

現在のパラメータ化テストは「不死者・悪夢」で最終侵蝕率がちょうど100%になる境界を通らず、現行実装の区間漏れを検出できません。修正時には100%の確率が100～119%区分へ入る専用ケースを追加します。

## 現在のテストケース

| 分類 | ケース数 | 固定する挙動 |
| --- | ---: | --- |
| 判定 | 6 | 技能値を加算しない失敗、通常結果の達成値0、難易度0、ダイス0と`yousei`、複数回の`yousei`、対決の同値 |
| ダメージ | 3 | 達成値からのダイス数、対決失敗、固定値とダイス軽減の順序 |
| バックトラック | 7 | 7種類のDロイス選択肢と各振り方の侵蝕率区分 |
| 合計 | 16 | 実行時計算の主要なルール境界 |

このテストによって、難易度0で自動失敗・ファンブルまで成功率へ含めていた問題と、ダイス0個に`yousei`を指定すると自動失敗でなくなる問題を検出しました。これらは回帰テストとして維持します。

## 実行方法

実行時計算のルール検証だけを実行するコマンドは次のとおりです。

```sh
npm test -- tests/runtimeRuleValidation.test.js
```

移行比較、共通分布、静的アセットを含むJavaScriptテスト全体は次のコマンドで実行します。

```sh
npm test
```

実行時計算を変更した場合は、JavaScriptテストに加えてESLint、markdownlint、本番ビルドも実行します。

```sh
npm run lint
npm run lint:markdown
npm run build
```

## 変更時の方針

ルール解釈、入力範囲、Dロイスの選択肢、結果区分を変更するときは、`dice-rules.md`、実装、独立テスト、この文書を同じ変更単位で更新します。

期待値の計算に本番のCalculator、FFT、生成器の内部関数、旧Calculatorを流用してはいけません。確率分布の比較では、理論上の完全一致が保証できない浮動小数点演算に明示した絶対誤差を使用します。

新しい事前計算効果を追加した場合は、その効果の確率分布自体を事前計算側で検証し、実行時計算側ではアセットの選択、他の修正値との合成、成功判定などブラウザで追加する処理を検証します。
