# 事前計算ロジックの検証方針

## 目的

この文書は、事前計算ロジックが[`dice-rules.md`](./dice-rules.md)の仕様と一致し、生成範囲全体で数値誤差が許容範囲内にあり、独立した乱数シミュレーションとも統計的に整合することを確認する方法を定義します。

既存JSONとの比較は移行時の回帰確認には有用ですが、旧実装と新実装が同じ誤りを持つ可能性を排除できません。そのため、検証コードは可能な限り生成器の数式、畳み込み、FFT、丸め関数を再利用せず、ゲーム内の手順を直接表現します。

## 検証レベル

検証は、独立した全列挙、全生成範囲の数値監査、乱数シミュレーションの3層で行います。

| レベル | 主な目的 | 実行タイミング |
| --- | --- | --- |
| 独立した全列挙 | 少数ダイスで各結果の確率が理論値と一致することを確認する | 通常のCI |
| 全生成範囲の数値監査 | 全入力について正規化、到達可能範囲、丸め、上限処理を確認する | 通常のCI |
| 乱数シミュレーション | 代表値と境界値で独立実装と統計的に整合することを確認する | 専用コマンドおよびリリース前 |

## 独立した全列挙

通常D10合計、`livingdead`、`kazanari`は、ダイス数0～4のすべての初期出目を列挙します。`kazanari`の振り直し結果は、独立したD10合計の出現回数を直接数え、初期ロールと組み合わせます。

実装済みの全列挙テストだけを実行するコマンドは次のとおりです。

```sh
uv run --project generator pytest generator/tests/test_exhaustive_reference.py
```

`kazanari`はダイス数0～4に対して、受理する対象数0～9をすべて検証します。対象数が現在のダイス数以上なら全対象を振り直すため、5～9個を指定してもこの範囲では新しい挙動は生じませんが、この同値性も境界条件として比較に含めます。

`dx`はクリティカルが任意回数続き得るため、有限個の出目列を単純に全列挙できません。一方、保存分布は達成値1023以上をインデックス1023へ集約するため、累積達成値が1023へ到達した継続状態は、その時点で末尾へ吸収できます。独立検証ではラウンドごとの全出目から終了時の出目と次ラウンドのダイス数を数え、未処理状態がなくなるまで有限状態DPを進めます。対象はダイス数0～4、クリティカル値2～11、受理する`shihai`の0～19すべてとします。

生成物は小数点以下6桁へ丸めるため、全列挙結果との各要素の絶対誤差は`0.000001 + 1e-12`以下を合格条件とします。相対誤差は、確率0付近で意味を持たないため使用しません。

## 全生成範囲の数値監査

全入力について次を検査します。

- 各確率が有限であり、保存後の値が0以上1以下である
- `dx`、`d10`、`livingdead`の確率総和が1である
- `dr`の確率総和が0より大きく、上限打ち切りを考慮して1以下である
- 理論上到達不能なインデックスの確率が0である
- ダイス数0、最大ダイス数、最小・最大の効果値で境界条件を満たす
- インデックス1023へ集約するデータセットで、上限超過後も確率質量が保存される
- 同じ環境と入力から同一のJSONおよびマニフェストを再生成できる

生成器は内部計算結果と保存用丸め結果を分離して取得できます。`generator/tests/test_numerical_audit.py`は、丸め前の確率が`-1e-12`以上、正規化対象の総和誤差が`1e-10`以下、保存後の各要素が0以上1以下、各要素の丸め誤差が`0.000001 + 1e-12`以下、保存後の総和誤差が`1e-12`以下であることを全生成範囲について検査します。`dr`は上限打ち切りがあるため、丸め前後の総和が0より大きく1を超えないことを代わりに検査します。

revision-2の全生成範囲を監査した実測値は次のとおりです。

| データセット | 分布数 | 丸め前の最小値 | 丸め前の最大総和誤差 | 最大要素丸め誤差 | 保存後の最大総和誤差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `d10` | 224 | 0 | `1.29e-14` | `8.85e-7` | `2.22e-16` |
| `livingdead` | 224 | 0 | `1.40e-14` | `7.61e-7` | `2.22e-16` |
| `dx` | 20,000 | `-4.44e-16` | `4.44e-16` | `9.00e-7` | `2.22e-16` |

`dx`の微小な負値は保存前の浮動小数点演算で生じ、設定した`1e-12`の許容値より十分小さい値です。保存後には0となります。正規化対象の最大要素丸め誤差が通常の四捨五入幅`5e-7`を超えるのは、6桁丸め後の総和を1へ補正する処理があるためです。

`dr`の2,030分布では、丸め前の最小値は`-5.38e-17`、最大要素丸め誤差は`5.00e-7`でした。一方、上限打ち切りで失われる確率質量は`kazanari = 9`かつダイス数202で最大`0.9989396105851173`となります。失われる質量が1%を超え始めるのは、`kazanari = 0`で171ダイス、`kazanari = 9`で163ダイスです。これは数値誤差ではなく現在の上限処理によるため、[`todo.md`](./todo.md)の`dr`統一課題で扱います。

## 乱数シミュレーション

シミュレータはNumPyの乱数生成だけを利用し、生成器の確率計算関数を呼び出しません。ケースごとに固定した乱数シードを割り当て、同じコミットでは常に同じ結果を再現できるようにします。

代表ケースには少なくとも次を含めます。

| データセット | 代表ケース | 乱数シード |
| --- | --- | --- |
| `d10` | ダイス数1、99、223 | 1001、1002、1003 |
| `livingdead` | ダイス数1、99、219 | 2001、2002、2003 |
| `dx` | `(dice, critical, shihai)`が`(1, 10, 0)`、`(10, 8, 0)`、`(20, 7, 3)`、`(99, 2, 19)` | 3001～3004 |
| `dr` | `(dice, kazanari)`が`(1, 0)`、`(50, 3)`、`(202, 9)` | 4001～4003 |

各ケースは200,000試行とし、確率分布の裾では期待度数が5以上になるまで隣接階級を統合します。適合度は統合階級に対するカイ二乗検定と、経験累積分布と事前計算累積分布の最大絶対差を併用して判定します。階級統合後に1階級だけになるケースはカイ二乗検定の自由度が0になるため、累積分布の最大差だけで判定します。

有意水準は検証一式あたり`0.01`とし、複数ケースにはBonferroni補正を適用します。累積分布の最大差には同じ補正後有意水準からDvoretzky–Kiefer–Wolfowitz不等式で求めた上限を使用します。統計検定に失敗した場合は、試行回数だけを増やして合格させず、乱数シード、ケース、最大差の位置、統合階級ごとの差を記録して原因を調査します。

シミュレーションは通常の`npm run generator:test`から分離し、`npm run generator:test:simulation`で実行します。全13ケースが約8秒で完了するため、CIとリリース前確認の両方で同じ試行回数、判定基準、乱数シードを使用します。

revision-2に対する実行結果は次のとおりです。Bonferroni補正後のケース別有意水準は`0.0007692308`、DKW上限は`0.00443375`です。

| ケース | カイ二乗p値 | 最大CDF差 |
| --- | ---: | ---: |
| `d10`, 1ダイス | `0.830456` | `0.001045` |
| `d10`, 99ダイス | `0.183305` | `0.001411` |
| `d10`, 223ダイス | 不適用 | `0` |
| `livingdead`, 1ダイス | 不適用 | `0` |
| `livingdead`, 99ダイス | `0.414345` | `0.001921` |
| `livingdead`, 219ダイス | 不適用 | `0.000012` |
| `dx`, `(1, 10, 0)` | `0.993899` | `0.001770` |
| `dx`, `(10, 8, 0)` | `0.171700` | `0.002338` |
| `dx`, `(20, 7, 3)` | `0.773650` | `0.000678` |
| `dx`, `(99, 2, 19)` | `0.604465` | `0.001121` |
