# 事前計算アルゴリズム

## 目的

この文書は、オフライン生成器が`d10`、`dx`、`dr`、`livingdead`の確率分布を計算し、配信用JSONへ変換するアルゴリズムを説明します。ゲーム内の手順と用語は[`dice-rules.md`](./dice-rules.md)、検証方法と許容誤差は[`precomputation-validation.md`](./precomputation-validation.md)、JSON構造と更新手順は[`precomputed-data.md`](./precomputed-data.md)を正規の仕様とします。

ここでは現在のPythonコードを行単位で説明するのではなく、同じ確率分布を再実装できるよう、確率変数、状態、漸化式、高速化、打ち切りを分けて記載します。生成器はブラウザやCloudflare Pagesの通常ビルドでは実行せず、データ更新時に開発環境で明示的に実行します。

確率分布、畳み込み、動的計画法、順序統計量、FFTを具体例から学ぶ場合は、学習用の[`probability-calculation-tutorial.md`](./probability-calculation-tutorial.md)を参照してください。

## 全体の処理

生成処理は次の段階に分かれます。

```text
ルールに基づく生の確率分布
  -> データセットごとの上限集約
  -> 小数点以下6桁への丸めと総和補正
  -> 先頭・末尾のゼロを除く疎形式
  -> shard単位のJSON
  -> 完全生成時だけmanifest.json
```

生の確率分布は`float64`のNumPy配列です。`dx`と`dr`は2048要素、`d10`と`livingdead`は1024要素で保持し、各配列の最終インデックスはその値以上をまとめたオーバーフローバケットです。

| 記号 | 意味 |
| --- | --- |
| `N` | データセットごとの最大ダイス数を含む分布数 |
| `S` | 確率分布の配列長 |
| `F` | D10の面数10 |
| `m` | `shihai`または`kazanari`の対象ダイス数 |
| `c` | クリティカル値 |
| `K` | 実数FFTの周波数ビン数 |

## 共通の分布操作

### ダイス分布

確率分布のインデックスを値、要素をその値の確率とします。通常D10はインデックス1～10へそれぞれ`0.1`を置きます。条件付きの低目D10は1～5、条件付きの高目D10は6～10へそれぞれ`0.2`を置きます。

0個のダイスの合計は0なので、畳み込みの単位元はインデックス0だけが1の点分布です。

### 逐次畳み込み

`convolution_powers`は、0個から`N - 1`個までの同一ダイスの合計分布を順番に作ります。1個前の分布を各面の値だけ右へ移動し、その面の確率を掛けて加算します。

```text
P_n[s] = sum(P_face[f] * P_(n-1)[s-f])
```

上限集約が有効な場合、右シフトで最終インデックス以上へ移る確率をすべて最終バケットへ加算します。一度集約された最終バケットも、以降の畳み込みでは最終バケットに留まります。

### シフト加算

`add_shifted`は、ある分布を指定値だけ右へ移動し、重みを掛けて別の分布へ加算します。`dx`のクリティカル1回分の10加算や、複数状態の混合に使用します。`subtract_shifted`は重みを負にした同じ操作であり、`dr`で条件に合わない場合を除外するために使用します。

## 通常D10合計

対象コードは`generator/src/dx_precompute/d10.py`です。

通常D10合計は、共通の逐次畳み込みをそのまま使用します。0ダイスの点分布から開始し、223ダイスまで直前の分布へD10を1個ずつ畳み込みます。

```text
S_0 = 0
S_n = S_(n-1) + X_n
X_n ~ Uniform({1, 2, ..., 10})
```

配列長は1024で、値1023以上をインデックス1023へ集約します。223ダイスでは理論上の最大値が2230になるため、逐次畳み込みの各段階でオーバーフローを保存する必要があります。

この方法はFFTより単純で、1回の生成で0～223ダイスの全分布を再利用しながら得られます。処理量はおおむね`N * S * F`、生の分布をすべて保持する配列部分は`N * S`です。

## 判定分布 `dx`

対象コードは`generator/src/dx_precompute/dx.py`です。`shihai = m`ごとに1 shardを生成し、各shardはダイス数0～99とクリティカル値2～11の組み合わせを保持します。

### 終了ラウンドの順序統計量

ダイス数を`n`とし、《支配の領域》と《絶対支配》によって大きい方から最大`m`個を1へ変更できるものとします。クリティカル値以上のダイスが`m`個以下になったラウンドで効果を使用すると、変更後に残る最大値は、変更前の出目を大きい順に並べた`m + 1`番目の値です。

`r = m + 1`番目に大きい値が`x`である確率は、二つの二項分布の上側確率の差で求めます。

```text
P(r番目に大きい値 = x)
  = P(x以上のダイスがr個以上)
  - P(xより大きいダイスがr個以上)
```

D10では1個が`x`以上になる確率は`(11 - x) / 10`、`x`より大きくなる確率は`(10 - x) / 10`です。終了値として必要なのは1から`c - 1`までです。`r`番目の値が`c`以上ならクリティカルダイスが`m`個を超えるため、そのラウンドは終了しません。

### ダイス数に対する動的計画法

固定した`m`と`c`について、分布をダイス数の小さい順に計算します。`n > m`のとき、クリティカルダイス数`k`が`m + 1`以上`n - 1`以下なら、達成値へ10を加えた後、次は`k`ダイスの判定になります。

```text
P_n
  = 終了ラウンドの順序統計量
  + sum(P(critical dice = k) * shift(P_k, 10))
```

遷移先の`k`は必ず現在の`n`より小さいため、`P_k`はすでに計算済みです。クリティカルダイス数の確率は、1個がクリティカルする確率`p_c = (11 - c) / 10`の二項分布から求めます。

### 全ダイスがクリティカルする自己遷移

`k = n`、すなわち全ダイスがクリティカルした場合だけ、次のラウンドも同じ`n`ダイスになり、通常のダイス数DPでは自己参照になります。この確率は`q = p_c^n`です。

自己遷移以外をまとめた一段階の分布を`stage`とし、全クリティカルが0回、1回、2回と続く場合を幾何級数として加算します。

```text
P_n = stage
    + q * shift(stage, 10)
    + q^2 * shift(stage, 20)
    + ...
```

シフトが配列長2048へ到達するまで加算し、インデックス0～2046へ入らなかった残りの確率をインデックス2047へ置きます。これにより、任意回数続き得るクリティカルを有限回の処理で表現します。`c = 11`では`p_c = 0`なので自己遷移はありません。

### ダイス数が対象数以下の場合

`0 < n <= m`では、最初のロールの全ダイスを1へ変更できるためゲーム上はファンブルです。`n = 0`はダイスを振らない自動失敗です。`dx`の内部表現では、どちらも実行時に同じ処理へ渡すためインデックス0の点分布として保存します。ゲーム上のファンブルと0ダイスの自動失敗の違いは[`dice-rules.md`](./dice-rules.md)に記載します。

### 計算特性

同じ`m`と`c`では、小さいダイス数の結果を大きいダイス数が再利用します。主な処理は、終了ラウンドの二項確率、最大`n - m - 1`個の下位状態のシフト加算、最大`ceil(S / 10)`回の自己遷移のシフト加算です。

1 shardの生配列は`100 * 10 * 2048`個の`float64`、配列部分だけで約15.6 MiBです。20種類の`shihai`は別shardとして生成・配信します。

## ダメージ分布 `dr`

対象コードは`generator/src/dx_precompute/dr.py`です。`kazanari = m`ごとに1 shardを生成し、各shardはダイス数0～202の分布を保持します。

### 低目と高目への分割

最初のダメージダイスを、振り直し候補になる1～5の低目と、保持する6～10の高目に分けます。`n`ダイス中の低目の個数`l`は、成功確率`1 / 2`の二項分布に従います。

```text
P(low count = l) = C(n, l) / 2^n
```

低目であると分かったダイスは1～5、高目であると分かったダイスは6～10の条件付き一様分布です。この分割により、低目の個数を固定した後は、低目側と高目側を独立に計算できます。

### 低目が対象数以下の場合

`l <= m`なら、低目をすべて振り直します。元の低目は結果から除かれ、新しい通常D10を`l`個振った合計へ置き換わります。高目`n - l`個はそのまま残します。

```text
term_l = D10^(*l) * HighD10^(*(n-l))
```

ここで`*`は畳み込み、`P^(*k)`は分布`P`の`k`回畳み込みを表します。

### 低目が対象数より多い場合

`l > m`なら、低目の小さい方から`m`個を除き、残った低目の合計分布`R_(l,m)`を求めます。その後、新しい通常D10を`m`個振って加えます。

```text
term_l = R_(l,m) * D10^(*m) * HighD10^(*(n-l))
```

`R_(l,m)`は、最後に除かれる`m`番目に小さい低目の値を閾値`t`として、`t = 1, 2, ..., 5`の排他的な場合に分けて計算します。閾値より小さいダイス数を`b`とすると`0 <= b < m`であり、値`t`のダイスを少なくとも`m - b`個除く必要があります。

値が`t`以上の低目の合計分布から、値`t`の個数が`m - b`未満である排他的な場合を引きます。除いた`m - b`個の`t`による合計`t * (m - b)`だけ分布を左へ移し、閾値未満だった`b`個の確率と組み合わせます。閾値未満のダイスはすべて除かれるため、この段階では個々の出目の合計ではなく個数だけが必要です。

1～5の各開始面について、開始面以上5以下の条件付き分布の0～202乗を先に逐次畳み込みで作り、`R_(l,m)`の各場合から再利用します。

### 二項混合とFFT

低目の個数ごとの分布を二項確率で混合すると、最終分布は次の形になります。

```text
P_n = sum(C(n, l) / 2^n * term_l, l = 0, 1, ..., n)
```

各`term_l`は複数分布の畳み込みなので、長さ4096の実数FFTへ変換し、周波数領域の要素積として計算します。通常D10、高目D10、振り直し後に残る低目の分布は必要なものを先にFFTし、同じshard内で再利用します。

最大202ダイスの合計は2020以下であり、FFT長4096に対して循環畳み込みの折り返しは発生しません。逆FFT後は2048要素へ変換しますが、現在の生成範囲では値2047以上へ到達しないため、`dr`のオーバーフローバケットは0です。

`m = 0`では振り直しがなく、通常D10のFFTをダイス数乗して逆FFTするだけの経路を使用します。FFT由来の絶対値`1e-15`未満の成分は0へ補正し、その後の数値監査で許容範囲を超える負値がないことを確認します。

低目の個数を0～`n`まで混合するため、shard生成の混合回数は最大ダイス数に対しておおむね二次的に増えます。FFTは各畳み込みを値領域で直接行う場合に比べ、分布長に対する処理量を抑えます。

## `livingdead`

対象コードは`generator/src/dx_precompute/livingdead.py`です。Dロイス《屍人》の結果は、通常D10の合計から最大目1個を除き、1を加えた値です。

```text
L_n = sum(X_i) - max(X_i) + 1
```

### 合計と最大目の状態DP

ダイスを追加する途中では、現在の合計`total`と現在の最大目`maximum`が分かれば、次のダイスを追加した状態と最終結果を決定できます。状態配列は次の確率を保持します。

```text
state[maximum, total]
  = 現在の最大目がmaximum、合計がtotalである確率
```

初期状態は`state[0, 0] = 1`です。新しい出目`face`を加える遷移は次のとおりです。

```text
next[max(maximum, face), total + face]
  += 0.1 * state[maximum, total]
```

各ダイス数の分布は、状態を`total - maximum + 1`へ射影して得ます。0ダイスだけは結果0の点分布とします。

### 安全な合計値の打ち切り

公開分布では値1023以上をインデックス1023へ集約します。最大目は10以下なので、合計が`1023 + 10 - 1 = 1032`以上なら、`total - maximum + 1`は必ず1023以上です。

このため状態DPの合計軸は0～1032だけを保持し、それ以上の確率をインデックス1032へ集約できます。以降のダイスを追加しても最終結果が公開範囲内へ戻ることはないため、この打ち切りは厳密です。

処理量はおおむね`N * 11 * 1033 * F`で、更新時は現在と次の2状態配列だけを使用します。各ダイス数の最終分布は別途保存します。

## 丸めと総和補正

各生分布は保存前に小数点以下6桁へ丸めます。FFTなどで生じる極小の負値は絶対値を取ってから丸めますが、実際の負値が許容範囲を超えていないことは丸め前の数値監査で別途検査します。

6桁丸め後の総和が1でない場合、丸め単位`u = 0.000001`ずつ補正します。総和が1を超える場合は、元の値に対して最も上方向へ丸められた要素から`u`を引きます。総和が1未満の場合は、最も下方向へ丸められた要素へ`u`を加えます。

```text
rounding error[i] = rounded[i] - raw[i]
```

この処理を総和と1の差が`u / 2`以下になるまで繰り返します。現在の生成物では保存後の総和誤差が`1e-12`以下であることを全分布について検証します。

## 疎形式とshard

丸め後の分布から、最初と最後の非ゼロ要素を探します。その間だけを`values`へ保存し、先頭インデックスを`offset`とします。途中にある0は位置を保つため削除しません。

```json
{
  "offset": 2,
  "values": [0.01, 0.02, 0.03]
}
```

`dx`は`shihai`ごとに20ファイル、`dr`は`kazanari`ごとに10ファイルへ分割します。`d10`と`livingdead`はそれぞれ1ファイルなので、完全生成では合計32アセットになります。

JSONは空白を含まない決定的な形式でUTF-8へ直列化し、末尾に改行を1つ付けます。全データを生成した場合だけ、各ファイルのバイト数とSHA-256を含む`manifest.json`を作成します。部分生成では不完全なマニフェストを作らないため更新しません。
